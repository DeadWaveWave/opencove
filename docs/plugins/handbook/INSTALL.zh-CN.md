# 安装、使用，并保留自己的工作

先准备一个来自可信作者的插件目录，其中应包含 `opencove.plugin.json`
和可直接运行的文件。OpenCove 不会替插件安装依赖或执行构建脚本。


## 从 Git 仓库安装

在**设置 → 插件**中选择**安装插件 → Git 仓库**，粘贴仓库 URL，再点击**安装插件**。
可选设置支持指定分支、标签或提交，以及仓库中的插件目录。此表单安装可直接运行的文件；
需要构建的插件请使用 [Git 分发指南](../DISTRIBUTION.md)中的显式 CLI 构建选项。

**发现插件**会搜索 GitHub 公开仓库。先检查项目，再选择它以填入仓库地址。
选择搜索结果不会自动安装。

Git 安装的详情页提供**检查更新**。查看结果后，可选择**应用更新**。
更新会在独立工作副本中合并，验证成功前保持当前版本运行。
发生冲突时会保留候选目录，供你检查和处理。更新成功后，请查看详情中的新源目录；
之前的工作副本仍会保留。

**历史版本**可恢复已保存的代码修订。它会保留用户数据，不会恢复旧的用户数据。
构建、冲突处理和命令示例见 [Git 分发指南](../DISTRIBUTION.md)。

## 连接到正确的 OpenCove

保持目标应用或 Worker 运行，在终端中查看已安装列表：

```sh
opencove plugin list --pretty
```

CLI 与运行中的应用应支持同一插件 API。如果还没有 CLI，可前往
**设置 → 连接 → CLI → 安装 CLI**。要恢复已停止的环境或准备独立开发环境，
请参阅[开发与验证指南](../AUTHORING.md#starting-a-matching-development-runtime)。
始终保持原来的配置目录或端点，不要随意切换到另一个运行中的实例。

## 从目录安装

使用插件在所连接运行环境机器上的绝对路径：

```sh
opencove plugin install /absolute/path/to/your-plugin --pretty
opencove plugin list --pretty
```

打开**设置 → 插件**，必要时刷新列表。点击插件查看 README、版本与交互预览。
安装目录不会自动上传到远程 Worker。

## 在画布上使用

回到项目画布，通过插件的操作栏或右键菜单入口创建窗口。
只有声明视图的插件才提供这些入口。插件也可能提供命令或 Skill，
可在其详情页中找到具体使用说明。

详情页的**显示位置**开关只隐藏快捷入口，不会停止已有窗口。
使用插件的启用开关来停止或恢复插件本身。

## 应用源文件修改

编辑或重新构建源目录后，主动加载新文件：

```sh
opencove plugin reload your-plugin
opencove plugin details your-plugin --pretty
```

将 `your-plugin` 替换为 manifest 中的插件 ID，并检查返回的版本修订与日志。
如果候选版本无效，之前正常工作的版本会继续可用。
源码版本管理属于你的源目录，重新加载不会替你合并 Git 修改。

## 遇到问题时

在插件详情中查看错误与运行日志。没有预览可能只是因为插件未提供预览入口。
窗口显示不可用时，检查插件是否已经安装并启用。停用插件不会删除保存的数据和窗口，
重新启用后可以继续使用。
